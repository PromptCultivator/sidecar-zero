# Kernel & Runtime Empirical Findings

[← High-level design](../docs/high-level-design.md) · [Canonical Benchmark Reference →](../docs/benchmarks.md)

Consolidated empirical results from the eight kernel and runtime validation suites in [`spikes/`](README.md), measured on Linux `6.12.76` (`aarch64`, cgroup v2) and Kubernetes `v1.37.0` (`containerd 2.3.4`).

| Validation Suite | Verified Property | Key Empirical Finding |
|---|---|---|
| [S1 — Sealed `memfd` across containers](s1-memfd-across-containers/FINDING.md) | Cross-container `SCM_RIGHTS` descriptor passing, cgroup v2 memory attribution, and `F_SEAL_FUTURE_WRITE` protection | Cgroup v2 charges shared-memory pages permanently to whichever container faults them first. Pre-faulting in the supervisor keeps 100% (`64.0 MiB`) of the arena in the sidecar's cgroup and `0 B` in the host container; omitting pre-fault shifts `63.7 MiB` to the host container as soon as it populates page tables. Read-only `F_SEAL_FUTURE_WRITE` mappings and cross-container `futex` wakes succeed under the `restricted` Pod Security Standard. |
| [S2 — OOM behavior matrix](s2-oom-matrix/FINDING.md) | Survival of PID 1 supervisor and warm standby under kernel OOM kills | Stock kubelet cgroup v2 sets `memory.oom.group = 1`, killing the entire container on an unshielded spike. Both `singleProcess` (`memory.oom.group = 0`) and `nestedCgroup` (per-worker child cgroups) preserve both PID 1 and the warm standby with zero container restarts. `oomScoreAdj` (`-1000`) preserves PID 1 but loses the standby worker. Adding `CAP_SYS_RESOURCE` to a non-root container with `allowPrivilegeEscalation: false` leaves the effective capability set empty (`EACCES`). |
| [S3 — Java FFM transport](s3-java-ffm/FINDING.md) | Zero-allocation FFM downcalls and virtual-thread carrier pinning on JDK 22 & 25 | The `VarHandle` + `futex` call path allocates `0 B/op` under C2, C1, and `-Xint` on both platform and virtual threads. Capturing `errno` or calling `MemorySegment.asSlice` allocates `40 B/op` outside C2 and is therefore forbidden on the hot path. Pinning all carrier threads in `futex` halts the JVM scheduler, whereas capping parked virtual threads at `carriers - 1` keeps unrelated virtual threads running smoothly. |
| [S4 — Arrow template interop](s4-arrow-templates/FINDING.md) | Cross-language acceptance of 64-byte capacity-spaced pre-stamped Arrow IPC `RecordBatch` frames | 162/162 pre-stamped frames across 3 schemas and 3 row counts are accepted with zero errors and exact FNV-1a checksum agreement by PyArrow/Arrow C++ (`26.0.1`), `arrow-rs` (`60.1.0`), Arrow Go (`v18.8.0`), and Arrow Java (`19.0.0`). Patch positions are derived by walking the Flatbuffer AST, and nullable columns are rendered with at least one null so stock writers emit a validity bitmap buffer. |
| [S5 — ONNX Runtime over foreign memory](s5-ort-foreign-memory/FINDING.md) | Zero-copy tensor binding over `memfd` slots, allocator trimming, and weight prepacking | `CreateTensorWithDataAsOrtValue` reads request slots and writes response slots in place with zero copies and `0.63 µs` fixed per-call overhead. Under ORT's default weight prepacking, matrix weights are copied into private RSS (`+38 MB` per worker); disabling prepacking (`SCZ_ORT_PREPACK=0`) shares file-backed weight pages across active and standby workers (`74 MB` vs `148 MB` combined PSS). |
| [S6 — Warm standby promotion](s6-standby-promotion/FINDING.md) | `worker_gen` promotion latency vs `pidfd` process teardown across worker memory sizes | Kernel `pidfd` readiness scales linearly with worker private RSS at `≈ 15 ms/GiB` (`15.68 ms` at `1 GiB`, `29.89 ms` at `2 GiB`) because `exit_mmap` runs before `pidfd` notification. Conversely, a robust futex lock held by the worker is released by `exit_mm` before `exit_mmap`, reporting worker death in `0.05–0.07 ms` regardless of worker memory size (`500×` faster at `2 GiB`). |
| [S6b — Per-thread early death signal](s6b-death-signal/FINDING.md) | Per-consume-thread robust locks across `musl` supervisor and `glibc` worker | Across 240 crash injections (`SIGKILL`, `SIGSEGV`, `SIGABRT`) up to `2 GiB` RSS, all 4 consume-thread death locks report in `0.05–0.13 ms` median, with zero worker instructions executed after the first report. Enabling core dumps delays the death lock to `289 ms` (`512 MiB` worker), which is why SidecarZero sets `RLIMIT_CORE = 0` by default. |
| [S7 — Platform & runtime invariants](s7-platform-facts/FINDING.md) | `SOCK_SEQPACKET` half-close, `tgkill` thread liveness, `clone3` seccomp fallback, file `ctime`/`mtime`, and `Loom` fences | `shutdown(SHUT_WR)` delivers `POLLIN \| POLLRDHUP` EOF to the client while allowing the supervisor to observe the client's subsequent `close()`. `tgkill(pid, tid, 0)` reliably detects exited threads (`ESRCH`). Containerd/Docker default seccomp profiles reject `clone3` with `ENOSYS` while allowing `clone(SIGCHLD \| CLONE_PIDFD)`. `Loom` requires explicit `fence(Ordering::SeqCst)` between release stores and acquire loads on store-buffering pairs. |

## Architectural Decisions Grounded in Empirical Findings

| Finding | Resulting Architectural Design in SidecarZero | Specification Reference |
|---|---|---|
| **S6 & S6b:** `pidfd` waits for `exit_mmap` (`≈ 15 ms/GiB`), whereas robust locks fire in `≈ 0.05 ms` | Every worker consume thread holds a kernel-watched robust lock (`WorkerSlot`). On the first lock release, the supervisor closes the gate and fails `READY` slots; as each thread's lock releases, its ring is repaired and handed over to the warm standby. Only `PROCESSING` slots wait for `pidfd` exit. | [04 — Supervisor §5.2](../docs/components/04-supervisor.md#52-detecting-death-and-hangs), [15 — Failure Modes §2.1](../docs/components/15-failure-modes.md#21-worker-killed-under-load-1) |
| **S6b:** Core dumps hold dying threads before releasing robust locks (`289 ms` delay at `512 MiB`) | The supervisor sets `RLIMIT_CORE = 0` on every worker before `exec` unless `--worker-core-dumps` (`worker.coreDumps: true`) is explicitly enabled for debugging. | [04 — Supervisor §5.1](../docs/components/04-supervisor.md#51-spawning), [05 — Worker §6](../docs/components/05-worker.md#6-sandboxing) |
| **S1:** Unfaulted `memfd` pages are charged to whichever container touches them first | The supervisor pre-faults 100% of both `memfd` segments (`MADV_POPULATE_WRITE` / stride write) before sending `WELCOME` so the arena is always charged to the sidecar container. | [01 — Shared-Memory ABI §7](../docs/components/01-shm-abi.md#7-file-backing-and-sealing) |
| **S1:** `SO_PEERCRED` returns `pid == 0` across separate container PID namespaces | Peer authorization checks UID/GID via `SO_PEERCRED`; the client PID in `HELLO` is recorded for diagnostics only. | [04 — Supervisor §4](../docs/components/04-supervisor.md#4-handshake-and-session-management) |
| **S2:** Privileged containers see the root node cgroup tree at `/sys/fs/cgroup` | Under `nestedCgroup`, the supervisor resolves its own container cgroup path from `/proc/self/cgroup` before creating `scz-supervisor` and `scz-worker-{0,1}`. | [04 — Supervisor §3](../docs/components/04-supervisor.md#3-startup), [12 — Kubernetes Deploy §5](../docs/components/12-kubernetes-deploy.md#5-oom-shielding) |
| **S3:** Virtual threads blocked in `futex` downcalls pin carriers invisibly to JFR | The Java FFM SDK caps futex-parked virtual threads at `availableProcessors - 1`, falls back to `LockSupport.parkNanos` (never `Thread.yield()`), and exports `Stats.parkedCallers()`. | [07 — Java FFM SDK §6](../docs/components/07-sdk-java-ffm.md#6-virtual-threads) |
| **S4:** Diffing renders misses equal fields; `arrow-rs` panics on out-of-bounds buffer slices | Worker template derivation walks the Flatbuffer table directly, renders nullable columns with a null so bitmaps are allocated, and validates buffer bounds before invoking generic Arrow readers. | [03 — Arrow Data Plane §8](../docs/components/03-arrow-data-plane.md#8-validation-and-safety) |
| **S5:** Default ORT prepacking duplicates matrix weights in private RSS | Memory sizing and standby fit checks account for private weight copies by default, and `model.prepack: false` (`SCZ_ORT_PREPACK=0`) is provided to keep weights shared in page cache when memory is constrained. | [05 — Worker §7.1](../docs/components/05-worker.md#71-onnx-runtime-backend-sidecarzero-worker) |
| **S7:** Unlinking or renaming over a model file updates `ctime` on the open FD | Model identity verification checks `(dev, ino, size, mtime)` and SHA-256 rather than `ctime` so atomic rename rollbacks succeed cleanly. | [04 — Supervisor §5.1](../docs/components/04-supervisor.md#51-spawning) |
