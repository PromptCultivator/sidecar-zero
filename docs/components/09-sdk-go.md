# 09 — Go SDK (`sdks/go`)

[← High-level design](../high-level-design.md) · implements [06 — SDK contract](06-sdk-contract.md)

The SidecarZero Go SDK (`github.com/PromptCultivator/sidecar-zero/sdks/go`, package `sidecarzero`) is a pure-Go 1.24 client with **zero Cgo** and **zero third-party dependencies** (relying exclusively on the Go standard library). It cross-compiles cleanly to any target OS/architecture, adds zero C toolchain requirements to application builds, and achieves zero heap allocations per call.

## 2. Public API

```go
import sidecarzero "github.com/PromptCultivator/sidecar-zero/sdks/go"

client, err := sidecarzero.New(
    sidecarzero.UnixPath("/run/sidecarzero/scz.sock"),
    sidecarzero.NewDenseF32Score(256),
    func(x []float32, _ sidecarzero.FallbackReason) float32 {
        if len(x) > 17 && x[17] > 0.8 {
            return 0.9
        }
        return 0.1
    },
    sidecarzero.WithSampleEvery(64),
)
if err != nil {
    log.Fatal(err)
}
defer client.Close()

out := client.Infer(features, 2*time.Millisecond)
```

### Mandatory fallback and input validation

- `fallback` is a required positional parameter to `New`; passing `nil` returns an error at construction time.
- `Infer` returns `Outcome[Out]` directly rather than `(Out, error)` because `Infer` never fails on its own account.
- Every prebuilt codec validates slice lengths against the bound template before writing to slot memory; short or oversized slices return a pre-allocated error value from `Encode`, releasing the slot and resolving to `FallbackReason::CodecError` with zero heap allocation.

### Metrics (`MetricsSink` & `PrometheusText`)

`client.Export(sink)` and `client.PrometheusText()` implement the unified metrics specification ([sdk-contract §7](06-sdk-contract.md#7-unified-metrics-and-hooks)), formatting floating-point sums and gauges identically to Rust's `f64` `Display`.

## 3. Shared memory and Unix socket plumbing without `x/sys`

- **Pure stdlib `net.UnixConn` (`unixpacket`) + `syscall`:** The handshake connects via `net.DialUnix("unixpacket", ...)` and receives the two `memfd` descriptors via `ReadMsgUnix` and `syscall.ParseSocketControlMessage` / `syscall.ParseUnixRights` (verifying `FD_CLOEXEC` on each descriptor). Because `conn_linux.go` uses Go's netpoller-backed `*net.UnixConn`, waiting for socket EOF occupies zero OS threads while the session is idle.
- **Mapping and atomic access:** `syscall.Mmap` maps `scz_ctl` (`PROT_READ`) and `scz_data` (`PROT_READ|PROT_WRITE`) as `[]byte` slices outside the Go garbage-collected heap. All shared-memory reads and writes go through generated methods on `abi.Seg` (`internal/abi/abi.go`) using `sync/atomic`. Narrow 8-bit and 16-bit fields (such as `cell.slab_class`) are accessed through their enclosing 32-bit aligned words. An AST/package lint test (`lint_test.go`) enforces that no code outside `internal/abi` uses `unsafe` or accesses raw arena bytes.

## 4. Calibrated monotonic clock

Calling `syscall.Syscall(SYS_CLOCK_GETTIME, ...)` directly bypasses the kernel vDSO and costs a full syscall on every admission check. Instead, `clock.go` captures `base := time.Now()` at startup alongside back-to-back vDSO-calibrated `clock_gettime(CLOCK_MONOTONIC)` samples to compute `offset`. On the hot path, `monotonicNs()` computes `offset + time.Since(base).Nanoseconds()`, which executes a single vDSO monotonic read in ~15 ns. The background monitor goroutine re-verifies `offset` every 250 ms and raises `CLOCK_FAULT` if drift exceeds tolerance.

## 5. Scheduler integration, spin EWMA, and parked-caller cap

### Service-time spin EWMA

Each caller entry tracks an EWMA of actual worker service time taken from completed slot records (`t_done_ns − t_enqueue_ns`), ensuring that scheduler wakeup latency never inflates the spin budget. When the remaining call budget after spinning would be shorter than the spin ceiling, the caller spins to the deadline rather than entering `futex` for a few microseconds (avoiding kernel timer-slack overruns).

### Parked-caller cap and OS thread bounding

When a goroutine blocks in `syscall.Syscall6(SYS_FUTEX, FUTEX_WAIT_BITSET, ...)`, the Go runtime detaches the logical processor `P` from the OS thread `M` so other goroutines continue running. To prevent a slow or hung worker from causing 1,000 concurrent goroutines to spawn 1,000 OS threads simultaneously:
- The SDK tracks the number of goroutines currently blocked in `futex` in an atomic counter.
- Below the cap (default `max(4 × GOMAXPROCS, 16)`), callers park directly in `futex`.
- Above the cap, callers use a short exponential-backoff `time.Sleep` poll loop that parks the goroutine in the Go runtime timer wheel without holding an OS thread.

## 6. Zero-allocation caller state, `Session` API, and stack-striped sampling

Because Go provides neither goroutine-local storage nor an exported goroutine ID, `Client` owns a fixed table of 1,024 cache-line-aligned `Caller` entries:

- **`client.Infer(in, budget)`:** Takes the address of a stack variable to compute a stack-page hash hint (`uintptr(unsafe.Pointer(&stackVar)) >> 12`), claims a `Caller` entry via `atomic.CompareAndSwapUint64(&entry.inCall, 0, snapID)`, and releases it before returning.
- **`client.Session()`:** Reserves a dedicated `Caller` entry for a long-lived worker goroutine (`s.Infer(in, budget)`), eliminating the per-call entry CAS overhead entirely.
- **Stack-striped sampling:** Call sampling (`WithSampleEvery(64)`) increments one of 1,024 cache-line-padded atomic counters indexed by the goroutine's stack-page hash. Because newly spawned goroutines reuse cached runtime stack segments, a server that spawns a fresh goroutine per request maintains accurate 1-in-64 sampling with zero allocations.

Verified in `sdks/go/test.sh`: `runtime.MemStats.Mallocs` and `TotalAlloc` deltas across 1,000,000 calls equal **0 allocations/call** and **0 bytes/call** across all execution paths, and `go build -gcflags=-m` verifies zero heap escapes on the hot path.
