# 10 — Rust SDK (`sdks/rust`)

[← High-level design](../high-level-design.md) · implements [06 — SDK contract](06-sdk-contract.md)

The SidecarZero Rust SDK (`crates/sidecarzero`, located at `sdks/rust`) is the reference client implementation. It is built directly on `scz-shm`, enforces `#![forbid(unsafe_code)]` across the client crate, uses a typestate builder to enforce mandatory fallbacks at compile time, and serves as the foundation for the [Python SDK](11-sdk-python.md).

To ensure that sharing `scz-shm` with the supervisor and worker cannot mask a shared layout bug, the Rust SDK is verified in CI against golden arena images in [`abi/golden/`](../../abi/golden/) generated by an independent tool (`scz-golden-gen`) that shares zero code with `scz-shm`.

## 2. Public API and typestate builder

```rust
use std::time::Duration;
use sidecarzero::{Client, Endpoint, DenseF32ToScore};

let client = Client::builder(Endpoint::path("/run/sidecarzero/scz.sock"), DenseF32ToScore::<256>)
    .fallback(|x: &[f32; 256], _reason| if x[17] > 0.8 { 0.9 } else { 0.1 })
    .build();

let out = client.infer(&features, Duration::from_millis(2));
```

### Compile-time fallback enforcement

```rust
pub struct NoFallback;
pub struct WithFallback<F>(F);

impl Client<(), ()> {
    pub fn builder<C: Codec>(endpoint: Endpoint, codec: C) -> ClientBuilder<C, NoFallback>;
}

impl<C: Codec> ClientBuilder<C, NoFallback> {
    pub fn fallback<F: Fallback<C::In, C::Out>>(self, f: F) -> ClientBuilder<C, WithFallback<F>>;
}

impl<C: Codec, F: Fallback<C::In, C::Out>> ClientBuilder<C, WithFallback<F>> {
    pub fn options(self, o: Options) -> Self;
    pub fn on_fallback<H: Fn(FallbackReason) + Send + Sync + 'static>(self, h: H) -> Self;
    pub fn build(self) -> Client<C, F>;   // only exists on WithFallback<F>
}
```

Calling `.build()` without first calling `.fallback(...)` is a compile-time error, verified by `trybuild` tests in CI. Both `C` and `F` are monomorphized into `Client<C, F>`, eliminating dynamic dispatch and boxing on the hot path.

## 3. Memory safety over shared memory (`ShmCell<T>`)

In Rust, forming a standard `&[T]` slice over shared memory that another process can concurrently mutate is instant Undefined Behavior (violating LLVM's `noalias` / immutability assumptions even if the values are never read twice).

Because the worker process has write access to the data segment, `scz-shm` and `sidecarzero` **never form a `&T` or `&[T]` reference into shared memory**:

| Operation | Safe API | Underlying access |
|---|---|---|
| Copy values out | `SlotReader::read::<T>(col, i)` / `SlotReader::copy_to(col, &mut [T])` | Volatile / atomic single-fetch reads copied into caller-owned stack or heap memory |
| In-place cell view | `SlotReader::cells(col) -> &[ShmCell<T>]` | `ShmCell<T>` wraps `UnsafeCell<T>`; `.get()` performs `read_volatile` |
| Write values in | `SlotWriter::write_from(col, &[T])` / `SlotWriter::cells(col) -> &[ShmCell<T>]` | `.set()` performs `write_volatile` |

The lifetime parameter `'a` on `SlotReader<'a>` and `SlotWriter<'a>` ties the borrow to the held slot guard, so the Rust borrow checker statically prevents any view from outliving the slot's `CLAIMED` or `DONE` state.

## 4. Caller state table, arena retirement, and fork safety

### Claimed `CallerEntry` table

Rather than storing per-caller state in `thread_local!` (which cannot be scanned by a background thread or isolated across multiple `Client` instances of the same type), each `Client` owns a fixed array of 64-byte-aligned `CallerEntry` structs composed entirely of safe atomics:

```rust
#[repr(align(64))]
struct CallerEntry {
    in_call: AtomicU64,          // 0 = free; otherwise (snapshot_id << 32) | kernel_tid
    cached_slot: [AtomicU32; 2], // per slot class
    ring_cursor: AtomicU32,
    last_call_ns: AtomicU64,
    breaker: Breaker,
    ewma: SpinEwma,
    counters: Counters,
}
```

On entry to `infer`, a caller claims an entry via a `SeqCst` CAS on `in_call` (starting at a fast thread-local index hint) and verifies that the active snapshot ID matches. A scope guard clears `in_call` on every exit path, including if a user codec panics (caught via `std::panic::catch_unwind` and converted to `FallbackReason::CodecError`, after publishing any claimed ring cell as `VOID`).

When retiring an old arena after a disconnect or supervisor-requested session reset, the background thread scans all `CallerEntry` records, ignores any marker whose `kernel_tid` is no longer a live task in `/proc/self/task`, unmaps the arena segments on the background thread, and closes the old session socket last.

### Fork safety (`scz_shm::fork`)

`scz_shm::fork` registers a process-wide `pthread_atfork` handler backed by fixed atomic tables of active client snapshot words and session socket file descriptors. When a process forks (for example, inside a Python server wrapping the Rust SDK), the child handler atomically zeroes all inherited snapshot words and closes the child's copies of the session sockets without allocating. When dropped in the child, `Client::drop` sees that `getpid()` differs from the creator PID and skips joining the parent's background thread.

## 5. `InProcessClient` test double and zero-allocation verification

`sidecarzero::testing::InProcessClient` executes the real `Codec` and Arrow template framing against an in-memory slot without requiring a sidecar process, and supports deterministic fault injection (`Fault::GateDead`, `Fault::Deadline`, `Fault::WorkerFailed`, `Fault::CodecError`, `Fault::Overloaded`, etc.) on any OS (Linux, macOS, Windows).

`sdks/rust/tests/alloc_gate.rs` installs a custom `#[global_allocator]` that counts per-thread allocations and asserts **0 allocations across 1,000,000 `infer` calls** across every model, fallback, overload, timeout, and newly-spawned-thread path.
