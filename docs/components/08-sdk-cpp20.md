# 08 — C++20 SDK (`sdks/cpp20`)

[← High-level design](../high-level-design.md) · implements [06 — SDK contract](06-sdk-contract.md)

The SidecarZero C++20 SDK is a header-only library with zero external dependencies beyond `libc` and the C++20 standard library (`libstdc++` / `libc++`). It throws no exceptions (`noexcept` throughout, compiling cleanly with `-fno-exceptions -fno-rtti`), performs zero heap allocations after client construction, and enforces the mandatory fallback policy at compile time via C++20 concepts.

All symbols reside inside `namespace scz { inline namespace v1 { ... } }` so multiple libraries inside one binary can embed different major versions without ODR collisions.

## 2. Public API and compile-time concepts

```cpp
#include <scz/sidecarzero.hpp>

scz::Client client{
    scz::Endpoint::path("/run/sidecarzero/scz.sock"),
    scz::codecs::DenseF32ToScore<256>{},
    [](const std::array<float, 256>& x, scz::FallbackReason) noexcept {
        return x[17] > 0.8f ? 0.9f : 0.1f;
    }};

auto r = client.infer(features, std::chrono::milliseconds(2));
std::string metrics = client.prometheus_text();
```

### Compile-time safety guarantees

- **Mandatory `noexcept` fallback:** There is no constructor overload without a fallback parameter, and the `FallbackPolicy` concept requires `std::is_nothrow_invocable_r_v<Out, const F&, const In&, FallbackReason>`. Passing a callable that is not marked `noexcept` or returns the wrong type fails to compile (verified by CMake `try_compile` negative tests in `sdks/cpp20/test.sh`).
- **Full monomorphization:** Both the codec and the fallback (plus the optional `on_fallback` hook) are template parameters on `Client<C, F, H>`, allowing the compiler to inline the entire call path without `std::function` heap allocations or virtual dispatch.
- **`[[nodiscard]]` and `noexcept`:** `Client::infer` is marked `[[nodiscard]]` and `noexcept`. Codecs report encoding or decoding errors via `bool` return values (`false` releases the slot and resolves to `FallbackReason::CodecError`).

### Metrics (`MetricsSink` & `PrometheusText`)

`Client` provides `stats()`, `export_metrics(MetricsSink&)`, and `prometheus_text()`. `PrometheusText` formats `double` values identically to Rust's `f64` `Display` (verified across 656,960 floating-point test vectors including exact halfway ties).

## 3. Shared-memory atomics and single-fetch reads

- **Generated `std::atomic_ref` accessors (`include/scz/abi.hpp`):** Every shared-memory word is accessed through generated functions wrapping `std::atomic_ref<T>` (and `__atomic_load_n` / `__atomic_store_n`) with the exact memory ordering declared in `abi/scz_abi.toml`. Control-segment accessors accept `const std::uint8_t*` and expose only load operations.
- **Single-fetch reads (`detail::fetch_once`):** Every field written by another process (`status`, `resp_len`, `resp_stamp`, frame row counts) is loaded once via `__atomic_load_n(p, __ATOMIC_RELAXED)` into a local variable before validation and use, preventing the compiler from duplicating plain memory reads across a bounds check (`TOCTOU`).
- **Shared `futex` syscalls:** Rather than `std::atomic::wait` (which uses process-private futexes), `detail/platform.hpp` invokes `syscall(SYS_futex, ...)` without `FUTEX_PRIVATE_FLAG`.

## 4. Caller state table and arena retirement

Each `Client` instance owns a fixed array of cache-line-aligned `CallerEntry` records:

```cpp
struct alignas(64) CallerEntry {
    std::uint64_t in_call;        // 0 = free; otherwise (snapshot_id << 32) | kernel_tid
    std::uint32_t cached_slot[2]; // per slot class
    std::uint32_t ring_cursor;
    Breaker       breaker;
    Counters      counters;
};
```

On entry to `infer`, the calling thread claims a `CallerEntry` via a `seq_cst` compare-and-swap on `in_call`, packing both the active `snapshot_id` (high 32 bits) and the thread's kernel TID from `gettid()` (low 32 bits) into the same 64-bit word. Packing both into one atomic word prevents any race between claiming an entry and reading a stale thread ID from a previous caller.

When retiring a disconnected arena, the background thread (`pthread_create`, with all signals masked via `pthread_sigmask`) scans all `CallerEntry` words. If an entry still references the old `snapshot_id`, the background thread checks whether `kernel_tid` is still alive via `tgkill(getpid(), tid, 0)`: if a thread was terminated mid-call (`ESRCH`), its stale marker is ignored so the old arena is still unmapped and the old socket closed without leaking memory.

### Fork safety (`pthread_atfork`)

A process-wide `pthread_atfork` child handler iterates over a static registry of live `Client` instances, marks each client `orphaned` (so its destructor does not call `pthread_join` on a non-existent background thread in the child), clears its snapshot pointer, clears inherited `in_call` markers, and closes the child's copy of the session socket.

## 5. Build, CMake integration, and verification

Applications consume the SDK via CMake:

```cmake
find_package(sidecarzero 0.1 REQUIRED)
target_link_libraries(my_service PRIVATE sidecarzero::sidecarzero)
```

`sdks/cpp20/test.sh` runs:
1. Compile-fail concept tests (`try_compile`).
2. Unit and protocol tests under standard flags, `-fno-exceptions -fno-rtti`, ThreadSanitizer (`-fsanitize=thread`), and AddressSanitizer + UndefinedBehaviorSanitizer (`-fsanitize=address,undefined`).
3. **Zero-allocation gate (`tests/alloc_gate.cpp`):** Overrides global `malloc`, `calloc`, `realloc`, `posix_memalign`, `aligned_alloc`, and `operator new` with per-thread counters and verifies **0 allocations** across all model, fallback, overload, timeout, new-thread, and `on_fallback` hook paths.
4. Multi-thread atomic stress tests and CMake installation consumer verification.
